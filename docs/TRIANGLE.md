## 我的默认选择：B，理由

1. 三个核心用户人设（重度多模型、隐私敏感、折腾型）的取舍判据是"协议健壮性 / 渲染性能 / 密钥安全"，这三项全部落在卓越线里，B 不砍它们。
2. 被 B 砍掉的东西（VAD 打断、语义召回、加密分享链接、class/state 图）都是**可后加且不移架构**的功能；而卓越线里任何一项如果晚做，都要返工数据层或渲染内核，代价是不可逆的。
3. M0 阶段最贵的错误是"契约与基准框架不完备就并行开工"，A 与 C 都会放大这个风险：A 让契约变更次数上升，C 让 Gate 退化为仪式。

## 开发侧预算（三方案共用）

- 总里程碑：8（M0~M7），Gate 未过不得进入下一阶段。
- 单任务单验收粒度：一次会话内可完成、可被一口气验收完毕。写不完就拆。
- 单任务单最长存活：1 次会话 + 1 轮返工。超过即视为拆分失败，重拆。
- 返工上限见上表；触顶则升级架构复盘，不许无限轮次。
- 每一轮 Gate 前必须有一次我亲自执行的对抗评审（准则 5），记录进 `docs/reviews/`。
