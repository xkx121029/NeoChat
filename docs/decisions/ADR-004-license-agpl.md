# ADR-004 — 开源许可：AGPL-3.0 与依赖政策

- 状态：**Accepted**（2026-11-22 人类指令）
- 影响范围：全部泳道、发布方式、依赖引入、外部代码参照

## 1. 背景

2026-11-22 人类指令：**项目以 AGPL-3 许可证开源**，并要求"大部分可以参照 https://github.com/ccch1mneyyy/dsh-Go 的代码"。

这条指令推翻了 ADR-001 与 `docs/security/README.md` 中"闭源分发、禁止 GPL/AGPL"的前提；D6 随之失效并在此重定。

## 2. 决策

1. 许可：**AGPL-3.0-or-later**，根目录 `LICENSE`，提交默认按此授权。
2. 依赖政策按 AGPL-3 重算（见 `docs/security/LICENSE-POLICY.md`）：GPL-3.0 / LGPL-3.0 / AGPL-3.0 由"禁止"改为"可用并保留声明"；**GPL-2.0-only 因不兼容而禁止**；SSPL / BUSL / CC-BY-NC 仍禁止。
3. 参照外部代码规则：只搬设计；直接复制须同许可 + 文件头标注来源 URL 与 commit sha + `THIRD-PARTY.md` 记录；不标注视为许可污染。
4. 分发影响：AGPL 有网络交互条款，将来若出现服务端组件（同步中转、分享链接服务），必须同样开源或另立许可决策；本期不涉及。

## 3. 后果

**正面**：可合法参照同许可实现；许可检查简化为"拦截 GPL-2.0-only + 非 OSI 许可"。

**负面**：
- 关于页与隐私政策必须声明 AGPL 与源码地址，商店合规表述要改。
- 第三方不可闭源使用本项目，商业路径受限——这是人类明确取舍。
- 参照外部代码需严格溯源，否则被追责时无法自证。

## 4. 复审触发条件

- 出现引入 GPL-2.0-only 依赖的需求
- 出现服务端组件
- 需要商业闭源分发
