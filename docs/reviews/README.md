# docs/reviews/ — 验收记录

本目录是**验收的唯一事实来源**。Gate 通过必须有这里的工件，缺失即视为未通过。

## 文件命名

| 类型 | 命名 |
| --- | --- |
| 任务验收 | `<task-id>-accept-<date>.md` |
| 返工指令 | `<task-id>-R<n>.md` |
| spec 评审 | `spec-review-<spec-file>-<version>.md` |
| Gate 记录 | `G<m>-<date>.md` |
| 对抗评审 | `adversarial-<gate>-<date>.md` |
| 双端一致性 | `parity-<date>.md` |

## 验收记录必须包含

1. 任务ID与验收时间、验收人。
2. 逐条对照验收标准的判定（通过/不通过 + 证据文件路径）。
3. 抽检说明：抽了哪几项、为什么抽它（必抽对方最可能偷懒的那一项）。
4. 命令原文输出（不是摘要）。
5. 结论：通过 / 返工（返工须链接返工指令文件）。

## 媒体

UI 验收录屏放 `docs/reviews/media/`，命名 `<task-id>-<flow>.mp4`。无障碍录屏必须包含 TalkBack/Narrator 的语音节奏（即不得静音后加速）。

## 禁止

- 用"已确认""看起来没问题"作为判定依据。
- 事后补拍且不标注。补拍必须在记录中写明 `补拍` 与可信度影响。
- 在没有任何工件的情况下写"通过"。
