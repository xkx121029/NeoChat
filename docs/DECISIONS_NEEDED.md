# docs/DECISIONS_NEEDED.md — 需人类拍板事项

分三档。"不给会怎样"是这一列存在的理由：让你知道拖延的实际代价，而不是一句"请确认"。

## 档 1：阻塞 M0（不解决则 M0 无法推进）

> 2026-11-22 更新：D1~D4、D7 已由人类裁决并落进 ADR 与 spec。**当前只剩 D5（远程仓库，硬阻塞）与 D6（许可证白名单，可直接批准默认方案）。**

| ID | 事项 | 选项 | 我的建议 | 不给会怎样 |
| --- | --- | --- | --- | --- |
| D1 | **质量三角 A/B/C** | A 全范围+顶级／B 顶级+固定时间／C 全范围+地板 | **B 生效**（2026-11-22 人类未否决 A/C，按我此前声明的默认推进） | 已解除，但任何新增需求都要重算三角 |

## 我发现的硬冲突（必须在动手前裁决，不许含糊调和）

1. **Windows 冷启动 0.8s vs WinUI 3 + 无 NativeAOT** → D2。这不是"努力一下"能解决的，是平台基线。
2. **"渲染视觉等价" vs 跨平台字体度量** → D3。字面等价不可能；不定义容差就没有验收判据。
3. **"密钥绝不明文" vs "密钥双端互通"** → D4。Keystore/DPAPI 密文不可跨设备解密，导出必须引入口令派生。
4. **"移动端断线重连与续传" vs "Android 后台被杀"** → 已在 R8 接受为产品限制：流式仅前台保证，UI 明示。若你要求后台可靠，需要前台服务 + 常驻通知，成本与商店合规都会上升，请明确。
5. **"顶级 Mermaid（100 节点 ≤200ms 不阻塞 UI）" vs "禁用 WebView"** → D7 + R17。原生布局引擎是本项目最大的一块自研，工期风险最高。
